# Code of conduct

Be respectful, test your changes, and take responsibility for what you submit.

## Contributions

- You are responsible for every line in your pull request, regardless of the tools used to write it. If you can't explain a change, don't submit it.
- Review your diff first. Remove debug output, dead code, unnecessary wrappers, unsolicited features and unrelated refactors.
- Match the existing style. This is a Lua mod for Project Zomboid; keep straightforward fixes straightforward.
- Never open a pull request without running the affected behavior in the actual game. State the exact build, game mode and scenarios tested. Simulated tests alone are not enough.
- Keep pull requests small: one fix or feature at a time.
- Be clear about incomplete validation. Don't imply that multiplayer, performance or save safety has been verified when it hasn't.

## Discussions

Criticize the code, not the person. Harassment, personal attacks and abusive comments will be removed. Report problems with reproducible steps and enough context to investigate them.
